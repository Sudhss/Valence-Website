Core features

Built the right way,
from the ground up.

Zero-overhead rendering

Custom QPainter loop draws only visible lines. No layout engine. No DOM. Renders well within the 16.6ms frame budget regardless of file size.

Logical cursor model

Cursor tracked as (row, col) and converted to pixels via O(1) monospace math only at paint time. No pixel-drift bugs.

C++ syntax highlighting

Hand-written tokenizer with no regex overhead. Identifies keywords, types, strings, and comments in a single O(n) pass.

Integrated build & run

Hit F5 to auto-save, compile with g++, and execute — all piped through the embedded PowerShell terminal. No context switching.

Line number gutter

Dynamic-width gutter that scales with digit count. Current line highlighted. Separated with a subtle 1px border.

Command-pattern undo

Every edit is recorded as a reversible action. Temporal grouping merges rapid keystrokes into logical undo units — Ctrl+Z undoes words, not characters.

Built-in judge

Store test cases beside the problem, then compile once and pipe every case through the binary. Verdicts are the ones you already know — AC, WA, TLE, RE — and a runaway solution is killed at the time limit without freezing the editor.

Run the tokenizer

Every character
goes somewhere.

This is Valence’s own lexer, ported line for line from cpp_highlighter.cpp — one pass, left to right, no regex and no backtracking. Edit the line, then take it apart and watch each character fall into the bin for the token it was classified as.

Performance verified

Tested with
hard data.

No automated GUI scripts. No random assumptions. We built a headless C++ benchmark suite to isolate the core data structures and measure latency at the nanosecond scale.

<9ms
End-to-End Logic Latency
The critical path (insert + undo record + full state rebuild + viewport tokenization) takes under 9ms for a 10,000-line file. Combined with ~4ms for QPainter, it fits comfortably in a sub-15ms frame budget.
56µs
Midpoint Insertion Penalty
We tested the O(N) worst-case vector insertion by splitting a 50,000-line document directly in the middle. The CPU cache absorbs the penalty—it takes just 56 microseconds.
45%
Memory Overhead
Valence stores raw text in native C++ strings. A 50,000-line file (~1.8MB of raw text) requires less than 4MB of heap allocation. Over 95% less memory than standard editors.
900k

Our zero-allocation, single-pass C++ syntax tokenizer eliminates Regex overhead entirely, averaging ~1.1 microseconds per line.
Methodology: Timings captured using std::chrono::high_resolution_clock running directly against Valence's core C++ objects (TextBuffer, UndoManager, CppHighlighter). Compiled with g++ -O2 on Windows 64-bit.

Tech decisions

Why every
choice matters.

  • Array of Lines over Rope

    Rope trees give O(log n) insertion but O(log n) line access. Our rendering pipeline needs O(1) line access 50+ times per frame — vector<string> is the optimal tradeoff for files under 100k lines.

  • Logical cursor, not pixel cursor

    Tracking cursor in (row, col) and converting to pixels at render time eliminates an entire class of drift bugs when the font changes or the viewport scrolls.

  • Viewport culling from day one

    Only draw lines between startRow and endRow based on scrollY. Rendering is O(V) where V ≈ 50 visible lines — a 100,000-line file renders at the exact same speed as a 10-line file.

  • Monospace font assumption

    charWidth measured once from 'M' at startup. Every pixel↔column conversion is O(1) integer math. Proportional fonts would require O(n) text measurement per call — a non-starter for 60fps.

TextBuffer.cpp 
void TextBuffer::insertChar(int row, int col, char ch) {
  col = std::clamp(col, 0, (int)lines_[row].size());
  lines_[row].insert(col, 1, ch);
}

void TextBuffer::deleteChar(int row, int col) {
  if (col <= 0) { mergeLines(row); return; }
  lines_[row].erase(col - 1, 1);
}

void TextBuffer::splitLine(int row, int col) {
  std::string tail = lines_[row].substr(col);
  lines_[row] = lines_[row].substr(0, col);
  lines_.insert(lines_.begin() + row + 1, tail);
}

void TextBuffer::mergeLines(int row) {
  if (row <= 0) return;
  lines_[row-1] += lines_[row];
  lines_.erase(lines_.begin() + row);
}
